## Android

A reviewable [store listing draft](STORE-LISTING.md) is included. Publisher fields remain explicit.

The project targets/compiles API 36, pins Build Tools 36.0.0 across app/library modules,
and supports API 24+. Google Play currently
requires API 36 for new phone app submissions:
[Google Play target API policy](https://support.google.com/googleplay/android-developer/answer/11926878?hl=en).

Install Android Studio Otter 2025.2.1 or newer, Java 21, Android SDK Platform 36, and build tools.
Set ANDROID_HOME to your SDK location or configure ignored `android/local.properties`.
The Android npm commands detect the scoped Java install at `~/.local/share/jetsweep-toolchain/jdk`,
Homebrew Java 21, and the standard macOS/Linux SDK directory
when no explicit environment is supplied. Existing JAVA_HOME/ANDROID_HOME settings take priority.
The runner is `scripts/android.mjs`; it builds/syncs before invoking the app module’s Gradle
task, which builds its dependencies without assembling unrelated library artifacts.

```sh
npm ci
npm run check
npm run android:debug
npm run android:lint
# android/app/build/outputs/apk/debug/app-debug.apk
npm run cap:android
```

The GitHub Actions workflow checks the web app, runs Android lint, and builds a debug APK
and unsigned release bundle with a provisioned Android SDK. It retains artifacts and lint reports. It has been added locally; it has not been run on GitHub in this session.

For Play release, open Android Studio and use Generate Signed Bundle / APK → Android App
Bundle. Create or choose the publisher's upload key outside the repository. Store credentials
in the CI secret store or ignored local files. `npm run android:bundle` generates the release
bundle but does **not** configure signing; an unsigned bundle cannot be submitted.

Before release:

- Confirm application ID, publisher, support contact, privacy URL, and version.
- Address legacy launcher icon shapes and add themed monochrome icons; review generated
  splash densities on devices. Prepare actual store screenshots,
  Play icon (512×512), and feature graphic (1024×500).
- Complete Data Safety, content rating, audience, and app-access declarations accurately.
- Test an API 24 device and a current API 36 device: gesture/three-button navigation,
  keyboard, landscape, font scaling, process restart, offline use, and system Back.
- Install the signed build through Play internal testing; run the pre-launch report.
- Confirm any account-specific closed-testing requirement in Play Console.

## iOS

The generated Xcode project uses Swift Package Manager, targets iOS 15+, and shares the same
web flow. Capacitor 8 requires Xcode 26+. Apple requires the iOS 26 SDK or later for current
uploads: [Apple SDK requirement](https://developer.apple.com/news/?id=ueeok6yw).

```sh
npm ci
npm run cap:ios
# In Xcode, choose a simulator and Run.
# For distribution, configure the owning team, then Archive and upload to TestFlight.
```

Before submission, confirm bundle ownership, configure Apple signing, verify privacy manifests
and App Privacy answers for the final SDK set, add support/privacy URLs and store artwork,
and test VoiceOver, Dynamic Type/zoom, landscape, safe areas, cold start, and offline behavior.
Simulator compilation does not replace a signed TestFlight/device check.
